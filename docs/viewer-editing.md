# Viewer: editing

- Editing is a **local sandbox** over data that is never mutated. [js/edits.js](../public/js/edits.js) holds an edit as a delta keyed by the object's **pristine origin** (`Name@x1,y1`, with `#n` in dataset order where the tuple repeats inside the path: 10 groups in Oddysee, 41 in Exoddus), per field and, where the object was moved or resized, its whole `rect`; it materializes a path carrying deltas as a new object over the pristine one — unedited TLVs kept by identity, edited ones fresh with `fields` spread (only where the pristine object archives any: a type without the key stays without it, which the surfaces fork on), the rect applied and `extra` derived again — and stands it in the dataset by cloning its level into `data.levels[j]`. An entry marked `removed` materializes the same way and goes into the fresh path's **removed list** (`removedObjects`, a WeakMap off the standing path; `isRemoved` answers for the object, `ghostOf` finds the ghost standing for a TLV) instead of its `tlvs`, so a ghost carries the deltas it was removed with and every helper reads it like a standing object: what the ghost shows is exactly what a restore stands. An **added object** is a `+n` entry carrying its type's name, its rect and, for a type that archives fields, all of them; it materializes through `newObject` ([js/objecttypes.js](../public/js/objecttypes.js)) after the shipped objects in the order the numbers were handed out, so the shipped objects keep their list positions (the brains' dice seed is an object's place in the list), its origin recording its key and no pristine: `pristineOf` answers the object itself, `isAdded` says so, `editedFields` is `{}` and `editNotes` is `added` alone, and `currentOf` finds it again across swaps by its key. `n` comes from the entry's `next` counter, which only grows while the entry lives (`applyStoredEdits` raises it past every number present when an entry was written without it), so a reference re-resolved by key can never land on an unrelated object; when the last object leaves the entry goes whole, counter included, and a high-water mark kept per place for the session, beside the trail, keeps a number from coming round again while a stale handle may still name it. The keys and the counter are read with a nine-digit bound, so a hostile store cannot mint a malformed key. The type table behind it (`typeTable(G)`, memoized per dataset) is built over the **pristine** levels, the ones `shipped(G)` recorded standing in for any a swap replaced, so it reads the same whenever it is first asked and whatever has been edited: per type its numeric `t`, its fields in archive order, the size most placements share and each field's most common value, which is what a fresh object is born with; a type whose placements carry no `fields` key gets none. The addable types are therefore the types the game in hand places, the four never-placed schema types left out. A path whose deltas are all gone materializes to the pristine object **itself**, so a revert is a swap and an unedited export's digest is structural rather than asserted.
  - Every swap of a standing level goes through `swapLevel`, in either direction: the dataset takes the level, `state.lvl` / `state.path` / `state.sel` follow by short, id and object key (a selected ghost staying selected while its object stays removed, `currentOf` first and `ghostOf` second), a demo path's session reveal is carried over, `pathorder.invalidateEntry` lets go of both game-wide memos (the elections, and the walks seeded from them: a level's own identity cannot miss a walk whose start another level's door decides), and `data-changed` (`detail: {game, lv, pa}`) tells the page. A memo keyed on path or level identity misses on its own; one keyed on the dataset must answer the event.
  - **The navigation seam resolves by key.** `setLevel`, `jumpToPlace`, `jumpToTlv` and the level and path buttons look their target up by short and id against the dataset, and the place-search index carries places rather than level and path objects, so a captured object anywhere lands on the tree now standing. A "same path" guard (`campanel`, `fieldpanel`, `place`, `a11y`, the edit panel) compares `game/lv/pa`, never identity: `selection-changed` re-fires on the same path after every pushed hash write, and a materialization would otherwise read as a path change.
  - One guard, `validDelta`, decides whether a field delta may exist, entered or restored: a field the pristine object has, and either the value it shipped with or an integer the archive's s16 word holds, labelled where `valueMap` has labels; the way back to what shipped is never refused, whatever a rebuild did to the labels. `validRect` is its twin for where an object stands: four s16 words, no negative size (a zero one ships), and the rect's top-left corner and its midpoint (`Math.floor((x1 + x2) / 2)`, the export's own formula) both on the path's grid, judged by column and row on each axis rather than by the folded cell index, which would let a column past the edge wrap into the next row; the two points are where Oddysee's and Exoddus's camera indexes list a rect, so an export never meets one off the grid. The shipped rect passes whatever it is (seven Oddysee DeathDrops reach past the grid). `fitRect` shifts a rect onto the grid with its size kept, clamping the corner per axis to `0 .. w·worldW − 1 − ⌊width/2⌋`, and answers null for one at least twice the grid's width, which a caller refuses with a toast. `freeSpot` answers where a new object goes near a rect: the rect itself where no object stands exactly there, else the first spot beside it (to the right, the left, below and above by its own size plus one, a grid unit at least, then a grid unit further out a ring at a time, then over it by grid units) that keeps the rect's screen, the cells of its corner and midpoint, and stands on nothing exactly, the rect fitted onto the grid where no spot does; measured over the shipped placements, a spot beside every object keeps its screen, the 494 Exoddus zones too big for one landing over their original a grid unit on. Every funnel throws without a level map for the game, so an integer `to_level` can never be derived.
  - The store is one localStorage key, `owm:edits`, read through `settings.js`'s guarded `store` and sanitized on read by shape alone (`{game: {"LV/PA": {next, objects: {key: {fields, rect, removed}, "+n": {name, rect, fields}}}}}`, each part optional, s16 integers, a rect of four with no negative size, `removed` only `true`, `next` a positive integer, an added entry needing a `\w+` name and a rect) with no version marker, as the settings are: the shape is the version. A delta equal to the shipped value, a rect equal to the shipped rect included, is removed, so the store holds differences only. Stored deltas apply inside `loadGame`'s chain, the one funnel every dataset passes through (`ensureGame`'s arrival included), after the editor sidecar has supplied the level map and the field tables the deltas are validated against — awaited there because the boot's own fetch of the pair can lose the race, and a label check against tables not yet landed waves a stale delta through. They apply by direct assignment rather than through `swapLevel`, nothing yet holding a dataset the page has not seen; `validDelta` and `validRect` refuse at load what a rebuild moved (an object, a field, a label, a grid), and a delta the disc has caught up with is refused beside them, since it no longer differs and a per-part revert could never take it away; both are dropped from the store, and `addGame` says how many were forgotten. A sidecar or a field table that fails leaves the dataset pristine and the store untouched, and `addGame` says that too. An embed applies nothing (`setEnabled(false)` in `main.js`) and cannot arm the mode. `warmShell` names the sidecar of a game with saved edits, so an offline boot can apply them.
- [js/extra.js](../public/js/extra.js) is the builder's `tlv_extra_ao` / `tlv_extra_ae` over the archive's field names: one rule per game and type naming the payload words the builder's guard counts, in word order, and the bucket read from them, with the builder's range guards, its door-number mask and its express-well alternative rule, the level short read through the sidecar's `level_short`. `tests/unit/extra.test.js` requires every shipped object to re-derive to its committed bucket, key order included (the display renders `extra` in insertion order), which is also the proof that the archive carries everything navigation reads. Key presence is semantic downstream (`destOf` forks on `view1_cam != null`), so a branch leaves a key out rather than zeroing it.
- **Edit mode** (`state.edit`) is a transient mode like the ruler: not a Display toggle, not a Setting ([docs/viewer-boot.md](viewer-boot.md)'s taxonomy), not in the hash, not in `SHOW_KEYS`. `#editBtn` (`aria-pressed`, the mode owning no region; `.chrome`) or `e` enters it; it refuses under `body.embed` and while the world graph is up (whose `MAP_KEYS` swallow `e`), leaves when the graph opens, and shares the click with the measuring tools by a mutual exclusion that runs both ways: `syncShow` leaves the mode when a tool arms, and the sidebar disarms the tools on `edit-changed`, the mode's own notification (`graph-changed`'s shape), which is also what takes the drawer off the map on narrow. The panel imports no module that imports it: `setEditMode` and `selectObject` are reached from above, and what the mode asks of the surfaces it shares the map with rides the event. It arms the level map for the game in hand from the editor sidecar and re-arms on a game switch.
  - The button and the key wait on the `editObjects` setting (off by default, under Objects and fields, bound like every boolean), which **arms the mode and never gates the data**: stored deltas apply and are marked whatever it says, so a visitor's map cannot change under them by flipping it. Turning it off leaves the mode; `editpanel.js` hides the button and refuses `setEditMode(true)` off `getSettings()`, and answers `settings-changed` for the flip. The setting's row is also where the device's edits are counted and forgotten, `#editsHeld` shown only while the device holds some; a `.st-row` is `display: flex`, so its `hidden` needs the `[hidden]` rule.
  - `state.sel` is the selected TLV, re-pointed by `swapLevel` and cleared on a real path change. The mode draws every marker whatever Markers for the rest says (`drawnAs` in render.js reads `state.edit` beside `show.markers`), so what the panel can edit can be clicked; a canvas click in the mode selects the first object under the point as the hover ranks them (`hitBoxes` in render.js: the box the eye sees there, a sprite's image or a drawn marker, before an unseen rect; the smaller box before the larger; the later-placed before the earlier among equals), and never follows; a screen-list row selects as well as jumps, a keyboard activation (`e.detail === 0`) moving the focus onto the panel. The selection outline is a transient drawn whatever `markerShown` says, as the highlight is; an **edited** marker's outline is drawn in the marker pass, outside `transients`, so an image export carries it, and an unedited path's exports stay byte-identical.
  - **Edited state is marked wherever it shows**, exports included, so that nothing showing edited data can pass for the game's own: the marker's outline; one line naming the changed fields in the tooltip, the screen-list row and the search hit (`editedFields`); `.edited` and `EDITED_NOTE` on the path button, the chip's tag and the place panel's line with its revert; the a11y sentence's clause (`placeSummary`); and every export name — `-edited` after the kind on the two PNGs and the JSON, and after `-demos` on the graph's SVG and PNG, whose title and node marks say it too, the flag read off the built nodes like `demo`. A copied object link names the pristine origin and its toast says the link opens on the shipped object.
  - `#editPanel` ([js/editpanel.js](../public/js/editpanel.js)) follows the numbers panel ([docs/viewer-panels.md](viewer-panels.md)): `hidden`-toggled, `role="group"` named by its title, the `float-opened` handshake — mutually exclusive with the numbers panel at every width, the two sharing a corner — and a bottom sheet on narrow. It shows every archived field (never `visibleFields`, `HIDE_WHEN_ZERO` or the picker: an editor shows the archive), a `<select>` over `valueMap` or an s16 number input, a `LIVE_WHEN`-closed row dimmed, and "shipped: N" with a ↺ beside a field that differs; a commit re-renders through `data-changed`, the control being worked keeping the focus.
  - **Moving an object** is a drag of the selection ([js/interaction.js](../public/js/interaction.js)): a press in the mode on the object the click would select (`hoverTlvs[0] === state.sel`, the click's own ranking and padding, so what selects is what drags; a mouse's left button alone) carries it instead of panning, past the pan's own slip, with the grab point held in world units off the rect's corner, so a pointer crossing the fold between two packed screens carries the object across the slack the way `wX` reads it and the spaced pitch needs no case of its own; the moving rect is snapped while Shift is held (`snapRect`, read off the move event itself: the rect shifted along x so its midpoint lands where `collide.js`'s `snapAt` would stand a sprite anchored there, by the object's scale through `onBackgroundPlane` and, in Oddysee, its own camera, the top edge untouched as the engine leaves y to the floor), fitted onto the grid (`fitRect`) and drawn as a dashed ghost (`setMoveGhost`, a transient beside the selection outline) until the release commits it through `applyRectEdit`, a release short of the slip being the click it always was. The hover and the tooltip rest while the hand carries (`updateHover` is skipped, the cursor reads `grabbing`, `move` over the selection at rest), a second pointer, a pointer the browser takes away (`pointercancel`) or Escape lets the object go where it was, Escape being heard by a capture-phase listener live only during a move so the panel's own Escape never closes on it, and so does the object leaving the path (`data-changed` with no standing object for it) or the mode ending under the drag; no click follows a carried or a let-go press. Shift with the arrows nudges the selection one world unit, and Alt beside it a grid square (`collide.js`'s `gridSize` by the object's `onBackgroundPlane`: 25 units, 13 at half scale; a step the size of the engine's grid square and not a snap onto the grid, so an object off the grid stays off it; the key handler's Alt guard lets the chord through only in the mode with a selection, so Alt with the arrows does nothing elsewhere), through the same funnel with `merge: true`, so a held key's autorepeat is one undo step and the two sizes share a run. The panel's actions row under the title offers `put back as shipped` while the object differs from the disc (`revertObject`, one step; each action button carries a stable `data-action`, and the re-render's focus restore finds it again or falls back to the panel itself, so a keyboard press never drops the focus to `<body>`). Its Place rows type the position (the whole rect moves) and the size (the top-left stays), `data-place` inputs the focus restore knows beside the `data-field` ones, with `shipped: x,y w×h ↺` under them while the rect differs, and its footer opens with the keys the selection answers to and counts the path's edits by kind (`editNotes`'s `moved` and `resized` counted apart). The surfaces mark a move as any edit (`isEdited`/`editNotes`: the field names, then `moved`, then `resized`), and a permalink keeps naming the shipped origin, resolved through the origins by `applyHash` ([docs/viewer-navigation.md](viewer-navigation.md)).
  - **Removing an object** is `removeObject` from the panel's actions row or Delete / Backspace with a standing selection (the panel's keydown, outside a form field, once per press; the route planner's own Backspace in [js/interaction.js](../public/js/interaction.js) yields while the mode has a selection, so one press never does both). The removed object stays a **ghost** while the mode is on: the painter draws `removedObjects(path)` as dotted outlines in the edit colour at the rects they were removed with, under `transients` and `state.edit` so an export and the mode-off map never show one, and gated by `markerShown` like every marker; the hover appends them after every standing object (so a ghost never outranks what is there) and its tooltip says `removed on this device` beside `click to select`; a click selects the ghost like any object, the panel then carrying `removed on this device` in its title, `restore` as its one action (its footer's key line saying so in place of the keys a standing selection answers to), and its Derived and Fields sections inside a disabled `<fieldset>` with their shipped columns, and no Place section; a selected ghost cannot be dragged, nudged or deleted again, and the route planner's Backspace is its own again while one is selected. A restore, from the panel or the screen list (`restoreHere`, the panel's, which the list calls), brings the object's category back on where the map's own rule, `markerShown`, hides it, as an addition does, so what came back is drawn, and a pen post the Barriers toggle already draws flips no filter. The screen list buckets a screen's ghosts into their categories beside the standing rows while the mode is on (a head shows when either is non-empty, the title counts `· k removed`), each row tagged and carrying a `Restore <name>` tool, and re-lists on `edit-changed` so the rows come and go with the mode. A permalink to a removed object resolves through the ghosts as well ([docs/viewer-navigation.md](viewer-navigation.md)), centring on the ghost and saying so. The footer counts `k removed` beside the fields and moves, and `gameEdits` counts a removal as an object edited, which is what the Settings row says.
  - **The trail is a trail of the store, never of the map.** A step is what a hand did to a path's deltas through the funnels, `applyFieldEdit`, `applyRectEdit`, `removeObject` (the `removed` flag, the other deltas kept; an added object's entry gone outright, no ghost), `restoreObject` (the flag gone), `revertObject` (one object's whole entry gone, fields and rect alike), `addObject` (a `+n` entry minted, every field validated through `validValue` against the type's defaults, which stand in for the shipped values on an added object in every funnel) and `revertPath`; every funnel but those two refuses a ghost (`locate` throws, by the object's identity or by the store's `removed` flag, so a handle taken before the removal is refused as the ghost is), and removing a ghost is no step, and the trail holds the path's store entry as it stood before each one, cloned because the funnels write into the live entry; it is kept per place (`game/lv/pa`) and for the session only, while the edits themselves persist. `undoEdit` / `redoEdit` put the held entry back into the store and swap, the way a revert does, so every surface follows through the swap that exists and nothing downstream knows a trail is there; a later slice's edit is undoable the moment its funnel records a step. A step may carry a tag: a merging call to `applyRectEdit` (a nudge, `{ merge: true }`) tags its step `rect:<key>` and joins the step before it instead of pushing one when that step carries the same tag, so a run of nudges on one object is one step however long it runs; a step of any other kind (a drag's commit and a typed value call without `merge`), an undo (which clears the tag of the step it leaves on top) or a redo (which pushes untagged) ends the run, and every step, joined or not, empties the redo stack. A boot apply and an orphan drop are no steps, an edit to the value or rect already standing is no step and no swap, and `forgetAll` empties every trail. The keys live in [js/editpanel.js](../public/js/editpanel.js): Ctrl/Meta chords never reach the map's key handler, and the panel refuses them in a form field, where the browser's own undo keeps the keystroke.
