# Test suites

## `python3 -m unittest discover -s tools/tests`

- No disc image is needed, and the sidecar reproducibility tests run from the committed caches; only the tests that probe the checkout itself (the member-type parser pair and the four cache freshness checks) skip, and only where no checkout is configured or found — `$ODDWORLD_DECOMP` naming a path that holds none fails them instead, a named location being an assertion rather than a hint — and the tests that encode through oxipng skip where none is on PATH, which is every CI run. CI clones the pinned revision into `$ODDWORLD_DECOMP`, reading `DECOMP_COMMIT` and `AO_COMMIT` off `paths.py` and fetching both by SHA, which is what makes the six run in CI; a clone step gone missing fails them rather than skipping, the variable being set either way.
- A parser reached only through a nested helper (AE's `positional_rows`, the enum body loop) can't be tested until it's hoisted.
- `test_sprites.py` pins each sprite codec against a frame lifted off a disc (`fixtures/sprite_frames.json`, with the sha1 of the rows it decodes to), the animation-table walk over a synthetic chunk, the texel alpha states, the packer and a family's sheet, each sheet's name and the directory it leaves holding nothing else (a family renamed only in case among what it clears), the shape of the curated animation list and the random-table search over a synthetic executable; the atlases themselves reproduce only on a disc machine, like the cameras.
- `test_release.py`'s `CommittedOverlays` holds every committed overlay to the committed base: every image an overlay names is decoded and held to its name, and every camera it draws over to the base's screen beneath it. Each image's folder and name are held in turn to the release whose overlay lists it and the camera, corner, layer or family its entry gives it, which no pixel check could see out of step, a patch moved by whole blocks still changing every block it covers. It runs in full every time and skips nothing on the record of an earlier run, since its pass is what lets the deploy publish and a skip is only as sound as the list of files it keys on. Decoding is nearly all of its cost, so its pixel checks decode over a process pool of one worker a core, their work in module-level functions the workers can import, and a new check over the committed art goes through the pool the same way.

## `npm run test:browser`

- `anchors.spec.js` is the [alignment anchors](viewer-geometry.md#alignment-anchors) as a gate, each pinned twice: its geometry as literals — where the marker draws inside its own 368×240 screen, hand-verified against the artwork once and frozen, never regenerated from `model.js`, which is what they test — and its pixels colour-agnostically, the screen's canvas region matching the committed cam PNG away from the markers and differing from it on the pinned outlines. A transform regression fails the numbers at zero tolerance; a painter regression fails the pixels.
- `smoke.spec.js` covers what breaks visibly: boot paints a map with a clean console, a view permalink lands where it points and `viewHash()` reproduces it (a plain view hash is never rewritten, so asserting `location.hash` survived would be vacuous), the view keeps that spot when a link is answered, or Gaps between screens flipped, while the map's box has narrowed and its observer has yet to report it, a link into a level's later path asks for none of the level's first path's screens, and one naming a path its level lacks selects nothing on the way, a boot falling back past it and a hash change leaving the view where it was, a click on a door follows it, `?embed=1` hides the chrome, a search Enter moves the view (to a plain view hash — a search jump writes no object token), the search box's × shows for as long as the box holds text (a Tab from the box reaches it, and pressing it clears the text and the scope and hands the focus back), a switch clicked leaves the keys to the map (a letter flips another toggle and an arrow pans the view while the clicked one holds the focus) while a text field keeps its own (a letter typed in the search box flips nothing, and a `/` typed in the numbers panel's filter stays there rather than focusing the search), a settings toggle survives a reload, and the remembered view (the Display switches and Objects filters) and the settings each keep only the switches set away from their defaults, a saved switch staying in either until it is set again though it matches the default.
- `offline.spec.js` drives the worker's sheet retirement: with "Keep the map on this device" turned on over a view whose objects are off, it seeds the live `CACHE_NAME` bucket with an Oddysee camera, a stale Exoddus Slig sheet, stale Oddysee sheets of a family no sidecar names and of the Scrab, a file under Oddysee's sprites that is no family's sheet and a stale Oddysee Slig sheet, in that order, then shows the objects so the page fetches the sheets it wants through the worker, recording which; the stray file and the stale Slig sheet must go, the stale Scrab sheet with them only if a Scrab sheet was fetched, while the camera, the other two and every fetched sheet stay. The order is what makes the poll sound: the worker walks the cache in insertion order, so a rule loose enough to take the camera, the other game's sheet or another family's has taken it before the two it must take are gone. A second test opens the Japanese Oddysee, seeds a stale copy of one of its patches beside a patch of the same screen at another place, a stale file of another name the page never asks for (a mask the screen's own would retire, its fetch racing the seed) and the base's own picture of the screen, and fetches the patch's current file through the worker, which retires the stale copy alone.

- The suite runs the engine's clock: no reduced-motion preference is set on the browser context, so sprites animate and patrols walk in every spec, and a spec that depends on movement waits on `patrolTick()` or `sceneTick()` through the page's own motion module, never on wall time.
- The specs probe the page through its own module singletons (dynamic import resolved against `location.href`) and settle the way `export.js` does (`preloadPath`, `artworkReady`, a synchronous `draw()`), once the canvas width has held still for three frames, since the sidebar's boot slide shrinks the canvas and recentres the view over the first frames; `deviceScaleFactor` is 1 for every spec, set once in the config; the anchor spec, the one that compares pixels against the artwork, additionally pins the levers that comparison needs: zoom exactly 1, `?embed=1`, every show/cats key seeded explicitly through `owm:view`, and the mouse never moved. In a `waitForFunction` predicate keep to synchronous reads (`location.hash`) — an async predicate returns a Promise, which the poller takes as truthy at once, so the wait resolves with the promise's first value instead of polling. A spec that reads what a route handler records waits for the response (`waitForResponse`), never the request: the request event can fire before the handler has run, and a count read then comes up short.
