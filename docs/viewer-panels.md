# Viewer: panels, search, dialogs and accessibility

- The collapsed drawer is `inert` (`syncMenu` sets it beside the menu-button state), so the controls it slides off-screen leave the tab order with it. Focus cannot enter an inert subtree at all: closing the drawer out from under the focused element moves focus to the menu button, and `/` has to open the drawer before focusing search rather than after.
- `#a11yStatus` ([js/a11y.js](../public/js/a11y.js)) is the one region that says where the map stands: a `.sr-only` `role="status"` div parented on `<body>`, written on a real path change with the game, the level's full name, the path and its curated or in-game name, how many objects the path holds, and that it carries a note where it does — the accent dot on the chip says that last one to everybody else. `#cv` takes the same sentence into its `aria-label` under `role="img"`, so the graphic is named with what was last announced rather than with a second wording free to drift from it; a name is not a live region, so it can be rewritten as often as it likes without a word being spoken for it.
  - Being a `<body>` child that nothing hides is the whole of its reliability. `display: none`, `visibility: hidden` and an ancestor the drawer has taken the screen from all remove an element from the accessibility tree, and a region outside that tree announces nothing at all — a failure with no visible symptom.
  - It settles before it speaks. `selection-changed` fires once per autorepeat of a held `[` or `]`, and a permalink into another level selects that level's first path on the way through, so a region written on every one of them would talk through a whole browse and name places nobody chose. Identity alone answers neither, both being real changes of path.
  - The toasts and the route bar's `role="status"` answer for an action just taken; this one answers for where you are, and it is the only region that does — which is why `#placePanel` gives up being one.
  - Deliberately not `.chrome`: an embed is this map inside someone else's page, where the canvas's own name is the only orientation on offer.
- `#placePanel` ([js/place.js](../public/js/place.js)) is disclosed rather than announced: `#placeBtn`'s `aria-expanded`/`aria-controls` pair is the route in, and opening it moves focus onto the panel — `tabindex="-1"` and a `role="group"` with a name of its own — so a reader reaches the section, the nickname, the flags and the note that the announced sentence leaves out. Focus lands on the panel rather than on the chip because the chip's own label is rewritten on every selection change, and an accessible name that changes under the focus *is* announced: parking there would double every step.
  - A re-selection of the path it already describes skips the fill, because the pushed hash rewrite re-fires `selection-changed` on the same path constantly, and a rebuild would throw away the reader's scroll position.
  - Chip and panel are hidden outright under an open drawer on narrow, since the drawer names the place in its own buttons — which means an open panel can be covered rather than closed, and that the focus move has to ask whether the panel is really rendered before making it.
  - Check chip geometry on the longest label either game has, AE BA P4 (`[Demo] Block 3 Slig Bunks: Crawling Sligs`) at 390px and narrower: a representative path is short enough to hide a width regression, and the chip sits above the corner buttons in paint order, so an overlap makes them unclickable rather than merely untidy.
- [js/placesearch.js](../public/js/placesearch.js) indexes the map's own places — a level, one path inside it, or one screen of a path — for the search box's Places group; it is not [js/place.js](../public/js/place.js), which is the where-am-I chip.
  - A candidate carries two indexes because one blob cannot serve both halves: the *names* (level name, curated or in-game path name, nickname, section) are matched by substring the way an object's fields are, while the `LV Pn` code is held as whole tokens (`["r2", "p1"]`) and answers a term only in full. Blobbed together, the `2` in `zulag 2` is answered by the `R2` every Rupture Farms Return path sits in, and the four the game does call Zulag 2 arrive buried in all eighteen.
  - A screen candidate (`R2 P1 C3`) carries its path's blob plus the tokens naming its camera (`c3`, `c03`, the full cam name), but is listed only when a query term matches one of those camera tokens — its blob is its path's, so a bare name query would otherwise drag every matching path's whole screen list in. Clicking one centers that camera.
  - A path indexes its level's name, so a level name finds what is inside it — but `rankPlace` leaves that name out, which is what puts `Monsaic Lines` above the five paths it just pulled in.
  - The group is counted and capped apart from the objects, taking neither `HIT_CAP` nor a `GROUP_MAX` slot from them, and the summary's hit count stays an object count — which is why it has to say "no object hits" when places are the only thing on screen. Its demo-hidden tally is the one number that counts both, since a place the setting keeps off the map goes missing the way an object does.
  - Scope applies as it does to objects, except that `path` scope drops the group: the only place in scope is the one you are standing on.
- [js/messages.js](../public/js/messages.js) resolves what a sign in the world actually says: `objectMessages` is the one place that knows how each type picks from its table, so the hover tooltip, the screen list and search can never disagree about a board's words.
  - It answers `[]` only for a board whose ids are all blank, which is the claim the surfaces render as "runs dark": 20 of Oddysee's 45 boards, every one a Rupture Farms Return copy of a board its first visit taught with, where silence alone would read as the map not knowing. Everything else that cannot answer is `null`, a type that reads no table and a sidecar that never arrived alike, since `loadJson` yields `null` for a file that failed and a map that has not read the table must not assert the board is dark.
  - A line carries a note only where something else contests it. For the two states of an `LCD` that means a switch that can actually flip: the engine hardwires ids 0 and 1 to never and always, so 26 shipped boards no switch can flip would otherwise name a switch state, pinned in `tests/unit/messages.test.js`. A live switch keeps its note even when only one state resolves text, that being exactly what decides whether the line appears at all.
  - The tooltip caps at three lines and the screen list carries the whole rotation, a board reaching fifteen messages; search blobs them all, so a remembered slogan finds the board. Button codes reach search as the words the reader sees, the same rule the raw-values setting follows.
  - The map's own Displays category is off by default, so a marker has to be turned on before it can be hovered; the screen list and search answer either way.
- `#camPanel` ([js/campanel.js](../public/js/campanel.js)) answers a coordinate rather than a selection, so it takes one from a click or from `l`. The pointer aims; the keyboard has only the view's centre, and a path's grid is mostly empty — the centre sits over no camera at all on 100 of the 191 shipped paths — so `nearestCam` gives it the closest screen instead of refusing on a coin flip. A click carrying no object keeps its own rule, dismissing on the void; one landing on a marker opens the screen the marker belongs to — not necessarily the screen clicked — and falls back to the clicked screen when that cell holds no camera.
  - Opening it from the keyboard moves focus onto it: `tabindex="-1"` and a `role="group"` named by its own title through `aria-labelledby`, so the camera and the object count are heard before the rows and are not written a second time. The container and not the first row, which would skip both and has nothing to land on at all when a screen holds nothing.
  - Closing hands focus back to whatever `l` was pressed from, which has to be read *before* the hide: hiding a subtree holding `document.activeElement` drops focus to `<body>`, and the next Tab then restarts at the top of the page. Only a keyboard open records an opener, so closing a panel a click opened moves nothing.
  - On narrow the panel is a bottom sheet at `--z-map-overlay`, under both the scrim and the drawer, so `l` closes the drawer first — the same reason `#numbersBtn` does.
- `#numbersPanel` ([js/numbers.js](../public/js/numbers.js), counting in [js/census.js](../public/js/census.js)) counts picked object types at four tiers at once; the screen tier is the cell under the *view center*, so it listens for `view-changed` — dispatched from `scheduleHash`'s debounced timer, the one funnel every pan, zoom and selection settles through — rather than for any pointer event.
  - A screen's objects bucket by the world cell their top-left corner falls in (`tlvCell`, the same cell rule destination resolution uses — the screen list's inventory rule), so the surfaces agree on what a screen holds and the bucketing cannot move with the pitch; counts ignore the category display filters the way search does, and follow the demo setting, tallying what hidden paths hold as a footnote.
  - The screen list keeps bottom-left and this panel bottom-right, so a desktop holds both; on narrow both become bottom sheets, so a `float-opened` event lets whichever opens close the other — narrow only, by design.
- `#anchorTip` ([js/anchortip.js](../public/js/anchortip.js)) explains any element carrying a `data-tip` attribute. The attribute is the entire interface — there is no registration call and none is wanted; a class like `.gloss` is only the visual cue, so a new consumer writes an attribute and no JS.
  - It is the sidebar's one tooltip: an `.actbtn` writes a `data-tip` and never a `title`, pinned in `tests/unit/markup.test.js` with the shape — each line capitalized and punctuated, describing the control or naming the gesture it wants (the ruler and route rows ask for one), and state-neutral, so a toggle's tip reads the same with its mode already up: `#graphBtn` keeps a noun phrase because a press-describing tip would lie while the diagram is up. A `title` remains where its words repeat the element's own `aria-label`, on the icon buttons and the minimap; and, still explaining rather than naming, on the place chip, the route bar's two link buttons and the world graph's two saves.
  - `syncMenu` hides an open tip when the drawer closes, the pointer's half of the focus move beside it. A mouse needs no such call, `pointerout` firing when an element leaves from under the cursor; the tap is what does, being the one gesture that shows a tip and then activates what it sits on, so on narrow a sidebar button can take its own anchor off-screen.
  - Because an attribute carries a string and nothing else, the line break is the content model: the first line is the summary, the rest a dimmer `.detail` block.
  - It is a `<body>` child and `position: fixed` because the surfaces that host one scroll (`#sidebar`, `#camPanelBody`) and would clip a tooltip parented inside them; that is the whole difference from `#tip`, which is absolute inside `#main` and clamps against the canvas. `pointer-events: none` is what stops it costing a click on the chrome it crosses.
  - Nothing here calls `preventDefault`: the tap must still reach whatever the anchor sits inside, so one tap both explains a field and ticks it.
  - `data-tip` is a pointer affordance and reaches no assistive tech, so a control whose tip carries a cost writes the same words into an `.sr-only` span it names through `aria-describedby`, as the JSON export button does for its mask warning; a tip that only explains stays an attribute.
  - `pointerover`/`pointerout` are filtered to `pointerType === "mouse"`: a touch fires both around its own tap, so an unfiltered pair would show the tooltip and hide it again inside one gesture.
  - Leaving is asked of the anchor (`anchor.contains(relatedTarget)`) rather than re-resolved from the attribute, so an anchor with element children doesn't flicker as the pointer crosses between them.
  - Check the placement against the bottom edge, where it flips above the anchor, and at 320px, where the width clamp engages.
- [js/dialog.js](../public/js/dialog.js) holds what every dialog shares: `trapDialogKeys` keeps the keyboard inside the open one, and `openDialog`/`closeDialog` toggle its `.open` class while an open dialog stands on a history entry of its own, so the back button closes it exactly as Escape does — going back is a phone's usual way out, and the press would otherwise leave the site, which on a first visit means leaving it with nothing to come back from.
  - The entry carries the URL it was pushed on, so the traversal that closes the dialog fires no `hashchange` and moves nothing on the map. The pending view write is flushed first (the `dialog-opened` event, which [js/navigate.js](../public/js/navigate.js) answers), or a pan settling onto that entry afterwards would make the same press undo the pan as well.
  - A close by any other route spends the entry with `history.back()`, so the visitor's next press is theirs again — and only while the pushed state marker says it is still the entry on top. The back press's own close is the one that must spend nothing, which is why the handler drops the entry before closing.
  - One entry and one close serve every dialog, two never being open together, and nothing is wired at import: the module has to stay importable in bare Node.
  - Never in an embed, whose entries land in the host page's back stack, where a dialog of ours has no business.
- `#about` ([js/about.js](../public/js/about.js)) is on the `.overlay`/`.dialog` + `trapDialogKeys` pattern, and the first to hold links, which is why the trap's tab set counts `a[href]`: the others hold only controls, so widening it changed nothing for them.
  - Its prose is static markup rather than built by the module, so the notice is in the page source with scripting off, and it is deliberately not `.chrome`, so it survives an embed.
  - The RetroAtlas line says *part of*, never *powered by*: the two sites share an identity and no code, so wording that implies a common engine would claim something untrue.
  - It states no licence, and that is a decision rather than an omission: the repo holds code written here, one vendored file under another author's copyright, and artwork this project cannot license at all, so a single line of terms in the app would claim all three.
  - What keeps two dialogs from ever being open together is not a stacking tier — the sidebar's `z-index` exists only inside the narrow media query — but that an open overlay covers every other opener and `trapDialogKeys` swallows keydown in the capture phase, which is why `?` does nothing behind one.
- `#whatsnewFilter` ([js/whatsnew.js](../public/js/whatsnew.js)) builds the What's New tag row from the tags `changelog.json` actually carries rather than from a list in the code, so a new tag needs no JavaScript.
  - Give it a colour rule or it takes the dim default, and add one word to `tests/unit/changelog.test.js`'s tag set, which is the only thing standing between a typo'd tag and a phantom chip nothing catches.
  - The chip's *fill* is what says on or off, because the text colour belongs to the tag. Do not reach for opacity: `fixed` is already dim, so fading it says nothing.
  - `flagship` is an entry's second axis rather than a fourth kind: a `"flagship": true` beside the kind it keeps, a chip appended after the sorted kinds so it lands where a sorted fourth tag could not, and a badge beside that kind on the entry (`labelsOf`, the one place in the module that names it).
  - A flagship answers to **its own chip alone**, which is what lets the three kinds switch off and leave the flagships by themselves. It cannot also answer to its kind's chip: every flagship is new, so an entry surviving on either label would leave the flagship chip inert, and one needing both would make the kinds' chips hide what the flagship chip is there to isolate.
  - `tiny` is the same axis pointing the other way: a second badge beside the kind, reached by the same `labelsOf`, and the one label in the row with no colour rule of its own — the dim fallback is precisely what a mark meaning *minor* wants to say, where flagship needed a foil. It earns no chip, and above all no default-off one: the button's dot is the newest entry's date, so a hidden newest entry would summon a reader to a panel where nothing had changed, and the near-daily rhythm of small refinements is itself what says the map is tended. Saying small is the whole of it: the entry keeps its date, its place and its prose. The two marks are mutually exclusive, test-enforced.
  - One `--foil` token, because the badge, its chip and the entry's rail have to agree on it. The chip takes it as a *fill* where the badge takes it as clipped text: `background-clip: text` would clip the chip's own fill away, and the fill is the on/off signal. Naming the on state (`[aria-pressed="true"]`) outranks the off rule from anywhere in the sheet, so off needs no flagship case at all. In the reduced-motion block the foil stays and only the sweep and the sheen go — the gradient is colour, the travel is motion.
