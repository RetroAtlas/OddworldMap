# The relive_api export

- `relive_export_{ao,ae}.json`: generated **and committed** viewer sidecar carrying everything the page needs to build a relive_api document itself — relive's schema and the collision links verbatim from their `tools/data` caches, the payload layouts the archive's field names join through, the pinned export fallbacks, and (Exoddus alone reading them from data rather than a constant) its Abe starts and mud table.
  - The schema, the layouts and Exoddus's tables come from the committed caches, which is why `--emit-field-data` can write it; the links come from the directory the build in hand has just written them to, the cache itself for the site build, so a scratch `--out` build's sidecar carries that build's links. A test compares both halves against the caches they copy: a served copy that drifted would export documents the builder cannot reproduce.
  - `enum_values` repeats the enum tables as ordered arrays because JS reorders an object's integer-like keys, so the order `schema_blob` reads out of `enums` has to be carried rather than inferred — `Enum_LevelIds` opens at `-1` and would otherwise come back last.
  - `level_short` is the builder's whole level-id → short map, every id of it: the served level list keeps one level per archive, so the Exoddus ender ids a destination names (7, 11–14) reach the page only through this key.
  - It is the one sidecar the page does **not** fetch at boot, unless the device holds saved edits for the game, which apply through its level map before the dataset is shown; otherwise nothing reads it until the JSON export button is pressed or edit mode is entered, and Exoddus' is 37 KB gzipped. `loadEditorData` memoizes one fetch per game, and the worker's shell rule takes it like any other root-level JSON, so an export works offline from the first use onward.
- `tools/data/relive_ao.json` / `relive_ae.json`: cached relive_api schema for the exporter that writes the level editor's JSON, parsed from the pinned `alive_reversing` checkout by `parse_relive_schema` ([tools/oddmap/relive.py](../tools/oddmap/relive.py)) — per object type the CTOR literal (relive's `object_structures_type`, not always the name `map_data` carries: our `LCD` is relive's `LCDScreen`, our `Switch` its `Lever` — fourteen placed types differ, seven per game) and its properties as relive reads them (display string verbatim, payload word from the data struct's real layout, byte width, registered type name), plus the AddEnum label tables verbatim and the collision-line structure. Same cache discipline as the decomp caches in [docs/decomp.md](decomp.md): re-parsed only when deleted, from the pinned checkout alone.
  - Property words come from computed struct layouts, never from the ADD order, because the two disagree exactly where a member name lies about its offset — `WordAudit` in `tools/tests/test_relive_export.py` pins the full set of such liars, so a new one fails a test instead of shipping wrong words — and a layout correction that answers one spends its entry there.
  - The parse validates every layout it computes against the decomp's own `ALIVE_ASSERT_SIZEOF` lines and raises on any type it cannot width or any enum registration it cannot value, so a thinner sweep fails rather than caching a guess.
- `tools/data/lines_ao.json` / `lines_ae.json`: generated **and committed** collision links, per level and path — the words trailing each line's coordinates and type, which the exporter needs and no viewer surface draws. Written off the disc by a normal build like `messages_*`, and deliberately kept out of `map_data`, the dataset first paint waits for: inlined on the lines they would add 27 KB gzipped to the Exoddus dataset for data nothing on the map reads. They reach the page only through the `relive_export_*` sidecar, fetched on the first export press.
  - A `columns` key names them in the record's own order, `norm()`ed to the display strings relive registers, so the export joins them by name the way it joins a property.
  - The offsets differ per game (`line_links` in [tools/oddmap/games.py](../tools/oddmap/games.py)): AO a pair of s32 at 0x0C and 0x10, AE five s16 from 0x0A. A subset build merges into the file the way `map_data` does, and a scratch `--out` takes its own copy rather than the committed one, so a verification build can `cmp` it.
- `python3 tools/relive_export.py --all --out <dir>` — every path as relive_api v4 JSON, the AliveTeam level editor's format, from the committed map data and caches alone (no disc, no site change): the cross-check artifact that lets our extraction be diffed against relive_api's own reader.
  - Which camera an object is listed under is the path chunk's own index table to answer, and the games answer it differently: Oddysee places a rect by its top-left corner, Exoddus by its midpoint. Read off the index table over both archives, each rule is exact on its own game's 5,625 and 10,602 objects where the other misplaces 3 and 835: the rects whose corner and midpoint fall in different cells, a subset of those straddling a boundary, mostly zones. `bucket_cells` follows the game's own rule; the viewer's `tlvCell` is a separate question and keeps the corner in both.
  - A property whose value the archive doesn't hold fails the run with a manifest and withholds that path's file — relive's importer *aborts the process* on a missing numeric key, so an incomplete file must never look whole; `--allow-incomplete` writes it anyway, manifest printed the same.
  - `EXPORT_VALUE_FALLBACKS` in [tools/oddmap/relive.py](../tools/oddmap/relive.py) carries the words relive reads that the archive doesn't capture, printed on every run and spent loudly once a rebuild archives the word — except MovieHandstone's, the meaningless high half of an s32 the archive drops by design, which stays; `ExportSweep` pins the set, so a new gap fails a test rather than shipping as a silent zero.
  - `python3 tools/relive_verify.py --dump-lvl AO R1 <out.LVL>` writes the LVL the reference exporter is pointed at, its path data the disc's own bytes and its `.CAM` directory names one letter off so relive cannot open a camera. That is not tidiness: `CamConverter` tells an AO cam by the Bits payload's strip sizes, a test no PS1 cam passes, so it reads every PS1 cam's FG1 in AE mode, and that reader `ALIVE_FATAL`s on an LZ-compressed sub-stream, which the discs open in both games. A camera it fails to find costs only the artwork, which the diff never reads; a camera it finds costs the whole document.
  - Known divergences from a reference export of the same path: instance-name counters can order differently, and the reference's schema arrays are unordered_map-ordered on its side, so any diff must compare structurally, never by byte — `tools/relive_diff.py` is that comparison, holding the fallback-filled values and AE's `num_muds_in_path` — the reference indexes the mud table by the path index it was handed, the engine and our export by level id — as counted non-fatal classes.
  - `--digests <file>` writes one canonical-form sha256 per path instead, which is what pins the page's exporter to this one. [js/reliveexport.js](../public/js/reliveexport.js) is that port — the same joins over the same caches, reached through the `relive_export_*` sidecar — and neither language can run the other, so both answer to `tests/fixtures/relive-digests.json`: `tools/tests` regenerates and byte-compares it, `tests/unit/reliveexport.test.js` hashes all 191 documents against it. `canonical` is the shared byte form (keys sorted, no whitespace), exact because no value in a document is a float or non-ASCII.
- `python3 tools/relive_verify.py` — the exporter's oracle: exports every path and runs each document through relive_api's **own** JSON reader (`tools/relive_check`, a shim CMake project over the checkout's `Source/Tools/relive_api` directory alone, which is self-contained and SDL-free unlike the decomp's root project), failing on any exception or silently remapped enum label. Needs cmake and the checkout at the pin (`pinned_checkout` refuses any other, and the five submodules the shim compiles against have to sit at their recorded commits); every run re-drives the build into `~/.cache/oddworldmap/relive_check` — a no-op when nothing changed, and a build dir stamped with another revision, or configured from another checkout of this repo, is wiped first, so neither a re-pin nor a second checkout is judged by the old binary — and outside the repo on purpose, since a binary written into a synced working tree can lose its code signature under it and the kernel kills it on launch. Each document is checked in a subprocess of its own, because relive aborts the whole process on a missing numeric property. The shim points easylogging at nothing but stdout on the way in: `ELPP_NO_DEFAULT_LOG_FILE` leaves the logger with file output on and no file to write to, so relive's first warning would dereference a null stream, and its diagnostics are the only thing that names the record behind a `WrongTLVLengthException`. CI clones the pin but never builds the harness (no cmake step, no submodules), so the unittest suite stays the CI gate.
