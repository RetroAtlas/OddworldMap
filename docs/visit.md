# Visiting a place in the game

- [tools/visit.py](../tools/visit.py) turns permalinks into a memory card, `visit.mcd`, holding one Oddysee save per permalink that starts Abe at the linked place; [tools/oddmap/savegame.py](../tools/oddmap/savegame.py) writes the save and [tools/oddmap/memcard.py](../tools/oddmap/memcard.py) the card, laid out the way DuckStation formats and writes one.
- The save is AliveLibAO's `SaveData` byte for byte, PS1 file header included: 0x2000 bytes, one card block, the checksum at 0x200 the wrapping sum of the 1919 words after it. Measured against a real v1.1 card: all fifteen of its saves' checksums agree and their fields read as the decomp lays them out, and `write_card(read_saves(card))` reproduces that card byte for byte.
- Loading one runs the game's own path start (`SaveGame::LoadFromMemory`, then Abe's `Motion_62_LoadedSaveSpawn`): it clears the objects, moves to the saved level, path and camera, puts Abe at the saved x and searches 60 units above and below the saved y for a line of the saved type (`1 << mode_mask`), standing him on it or letting him fall, and rewrites the switch states and every object record's flag and state bytes for the whole level from the block at 0x2B0. Whichever records that block leaves uncreated spawn afresh, which is what makes a visit start the path the way a first arrival does.
  - **The block cannot be zeros.** It rewrites each record's flags byte whole, the end-of-list bit included, and a list left without its end bit runs on into the next camera's. `tlv_flags` copies the disc's own bytes in the order the game walks them: every path the level's table names (`tools/data/pathdata_ao.json`), camera by camera through the index table, each list to its end bit, entries at or past 0x100000 skipped.
  - The walk covers every path in the table, as the decomp's `kMaxPaths` loop does, not the path count `gMapData` carries: that count would leave out D2 P10 and R6 P6, and real saves carry both. Real saves for D2, R2 and R6 put every end bit where the disc walk does.
  - Every Oddysee level's block fits the 7501 bytes the struct gives it (R2, the largest, takes 3634). S1, the menu, has no table and is refused.
- The place is the permalink's object (its rectangle's centre x, searching down from its top), else its view's centre, else `--at`. Abe stands on the first floor or background floor at or below that point (`floor_under`), at half scale on a background floor, in the camera whose cell holds his feet. A floor of the same type within 60 units above that one would catch the game's search first, and the tool reports it, as it does a place outside the camera's 368×240 window.
  - A continue point brings its zone, clear range and rectangle, as touching it in the game would, and Abe faces the way it respawns him. Any other place gets zone 0 and a continue-point-sized rectangle at the landing spot, so a death respawns Abe where the visit began.
- The file header (title frame, palette, icon) is the first of the two `SC` headers in `SLUS_001.90`, the one a save whose alternate-header flag is clear wears. The title written into it is what the game's Load screen shows for the save. The card file name is `BASLUS-00190ABE` and five characters from the range the game's own names use, the prefix being what the game lists the card by.
- `--launch` points DuckStation at `<out>/profile` through the variable its data root is picked by (`Core::SetDataRoot`): `HOME` on macOS, whose root is `$HOME/Library/Application Support/DuckStation`, and `XDG_CONFIG_HOME` on Linux, whose root is `$XDG_CONFIG_HOME/duckstation` whenever that is absolute. The profile is made once from a copy of the real folder's `settings.ini`, found by the same rule, with the achievements login stripped, card 1 a shared card at `visit.mcd` and the BIOS images copied, and nothing in the real folder is written. Deleting the profile folder remakes it from the current settings on the next launch. Checked on macOS; the Linux path follows the source and has not been run.
  - Windows picks its root from known folders no variable moves, and a portable install (a `portable.txt` or `settings.ini` beside the program) always uses the program's own folder, so `--launch` refuses both and names the card to mount instead.
  - The Load screen opens on slot 1 and offers Switch Memory Card, so the card mounted in slot 2 of another profile should serve as well; that is untried.
- Exoddus saves a different struct (`Quicksave`): world info, then a serialized object list holding a 216-byte Abe record, then flags for only the record types its attribute table names. No real PS1 Exoddus save has been read against that layout yet, so `#AE` permalinks are refused until one is.
