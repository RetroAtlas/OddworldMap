# Viewer: navigation, routes and the world graph

## The order a level's paths are listed in

- `visiblePaths` in [js/navigate.js](../public/js/navigate.js) is the one place a level's path order is decided *for the buttons* — the path buttons, the path a level opens on and the `[` / `]` stepping all read it, so an order that reaches one reaches all three. The world graph is the exception and says so on its own bullet: its rows are the walk itself, whatever the setting, because there the order is geometry rather than a listing. The "Paths in play order" setting routes it through [js/pathorder.js](../public/js/pathorder.js), which returns a permutation of what it was handed and never filters: visibility and `revealPath` stay the caller's business, which is what keeps the module clear of `pathvisible.js`.
  - `levelOrder` is the order itself, one walk of the level's own trusted transitions out from the way in, memoized over every path the level has; `orderPaths` only sorts what it is handed by that, so a subset comes back in the same order and the demo setting cannot change what the order is. Twelve of the 25 levels come back exactly as they ship, Paramonia and Scrabania among them: their stored order already is the walk.
  - An **area** is what a path's name names with the `[Demo] ` mark and anything after a colon dropped, so a secret area, a sub-room and a demo copy all belong to the area they name, while a path the discs never named is an area of one. An area is walked whole before the walk leaves it, which is what holds Zulag 1's five paths together where the way on out of it sits two rooms in and a dead end is still unvisited behind it.
  - Branches are chosen by **the run the level counts itself in** — the numbered run naming the most of its areas, the Brewery's fourteen zulags rather than its three hubs, since numbers only ever compare inside one run. The branch whose number comes soonest goes first, which puts FeeCo's unnumbered corridor ahead of the terminal beside it (terminal 3 is behind it) and the Brewery's second hub behind the five zulags the first one serves. A branch reaching no number at all is a pocket off the route and is looked into before the walk moves on, which is the Mudomo Vault's third room. After all that, the lowest path id.
  - Inside an area, the same walk again from the path it was entered at, then whatever it missed, a sub-area behind its parent and a demo copy behind both. A path you can only come back from goes before one that carries you on — the pocket rule at path scale — and a way out of the level carries on like any other, which is what puts Rupture Farms Return's Zulag 1 Boom Machine room second and its Zulag 4 exit to the Board Room last, behind the two rooms that unlock it. Those and Zulags 2 and 3 are the only four places in either game where an area offers the walk a choice at all; the two hubs' spokes have nothing to rank them and fall to the path id.
  - An area nothing travels to still slots into its run by number, which is what lands the Mines' `[Demo] Tunnel 5: Blind Mudokons` between `Tunnels 3-5` and `Tunnel 6`, no other path naming the area it copies.
  - An Exoddus level's ender half sits at the level's tail in the order the walk met it, and that is the one thing outranking the walk: `BW P9` is the only path in either game listed ahead of what reaches it, its Executive Office being reachable only through the ender's own approach.
  - `levelEntry` elects one way in per level — an arrival from a level earlier in `data.levels`, else `AbeStart`, else any arrival — and the walk starts there. Deliberately not `computeEntryPaths`' set, which carries a later level's door back in (`R2 P11` is the Board Room's) and an `AbeStart` sitting deep inside a level (Bonewerkz' is in Annex 8); both games' elections agree with the decomp's own level-select tables, `sLevelList_4D0300` and `gPerLvlData_561700`. The destination rules it asks read the dataset's own geometry, never `LAYOUT` ([docs/viewer-geometry.md](viewer-geometry.md#the-gaps-toggle-and-the-cell-grid)), so the gaps toggle can never reorder a button.

## Routes

- A route ([js/route.js](../public/js/route.js)) is a list of per-path segments `{lv, pa, pts}`; an armed follow seams two segments (`routeSeam` before the navigation, `routeArrive` anchoring the far side on the partner), and a same-path door pair seams exactly like a cross-path one — the polyline break is the point.
  - The one survival rule: the route lives while the selection stands on **any of its segments' paths** — so the recipient of a shared link can walk it by button, door or the back button, and only a selection the route never visits clears it. The armed follow appends its destination segment before navigating, which is how a seam into fresh territory passes; that only holds because targeted navigation (`navigateToDest`, the jump helpers) switches levels through `setLevel`, which elects no default path — `selectLevel`'s first-path selection in between would fire the rule against a path nobody chose.
  - The token is `route=nCOUNT;sLV.PA;x,y;…;end`: the count first so it outlives a cut, a marker opening every segment so no waypoint can rebind to artwork it wasn't plotted on, `end` proving the payload complete.

## Permalinks

- Every coordinate a permalink carries is a **world** coordinate: the view centre, the object anchor and the route's waypoints alike. Draw space is a packing of the world that a change of pitch would slide under a link; a world point names a place in the game.
  - `parseHash` reads the text alone and `hashToDraw` resolves the coordinates against the layout it is handed, which `applyHash` passes only once the link's own game has been selected. Converting inside `parseHash` would read a link against whatever game happened to be loaded, and `sanitizeLocationHash` calls it at boot with no geometry at all.
  - There is no version marker and no fallback: a viewer meeting numbers it cannot read drops the view and fits the path instead. Shared links are live, so treat the shape as fixed and add to it rather than redefining what a token means.
  - `scheduleHash`'s push-ness is sticky until the write fires (a follow's history entry must survive the silent writes riding its heels), and the seam calls `flushHash()` first, so the entry left behind holds the route as plotted — both were found by watching the back button lose the follow.

## The world graph

- `#graphView` ([js/graphview.js](../public/js/graphview.js), aggregated and laid out by [js/worldgraph.js](../public/js/worldgraph.js)) is the whole game as one diagram in place of the map: a column per level in `data.levels` order, its paths stacked in `levelOrder`'s, and an edge for every transition the map already believes between two of them. A mode is not a float, so it takes **no stacking tier** — a positioned sibling after `#cv` covers the canvas, and every tier above it (the toasts, the drawer, the map chrome, the dialogs) keeps standing over it untouched. What that leaves is the map's own furniture. The floats close themselves — each answers `graph-changed` the way it answers a path change, because a panel merely hidden under the mode still answers Escape and comes back describing a view nobody is looking at — so `body.graph` is left with the surfaces that repaint themselves back into sight (`#minimap` unhides from inside `draw()`) and the sidebar buttons that act on the map: one saves the covered canvas, one paints its own image of a map nobody is looking at, and one would put a float the mode has just dismissed straight back over it. The Display toggles stay, since a checkbox records its own new state; that is the same line the swallowed keys are drawn on.
  - The canvas is covered, never unlaid-out: `fitView`, `centerOn` and `navigateToDest` each re-`requestAnimationFrame` while `cv.clientWidth` is 0, so a `display: none` would spin a frame loop for as long as the mode is up and hold a node's own jump until it closed.
  - Rows are the play-order walk whatever the "Paths in play order" setting says, because the walk is what makes the diagram legible: against the order the discs store, over the 62 and 86 undirected pairs inside a column, summing |row(a) - row(b)| on the rows the diagram draws, it comes to 125 against the stored order's 181 in Oddysee and 227 against 406 in Exoddus, and leaves one interleaved pair of arcs per game.
  - An edge is the pair of paths with a count each way, and an arrowhead marks a one-way link and nothing else — 13 Oddysee pairs and 28 Exoddus ones, against the 64 and 69 that run both ways. A head on every travelable end would spend the mark on the pairs that are ordinary and leave nothing for the ones that are not. Which end it goes on is `fwd`/`rev`, never the polyline's own direction: 4 Oddysee pairs and 11 Exoddus ones run *backwards* along the node order, and a head read off the line would point the wrong way on all fifteen.
  - Routes are orthogonal polylines, lane-packed per gutter: a level's own edges hug their column, an edge to the next level along crosses one gutter, and one reaching further travels the band above every column. The lanes are what keep two routes off one line, and a gutter is only as wide as the lanes it carries. Straight centre-to-centre lines are what this buys off: they pass through a box belonging to neither end on 36 of Oddysee's 77 lines and 54 of Exoddus' 97, where the routed ones do it on none. `tests/unit/worldgraph.test.js` sweeps the shipped data for a route that leaves the diagram, crosses a node box on either axis, bends off-axis or shares a line.
  - Each edge leaves a box on a line of its own, spread across the box's own height, up-bound stubs above down-bound ones and the nearer turn where it cannot cut across a farther one. Every edge departing at the box's middle instead put 154 pairs of Oddysee segments and 235 of Exoddus' on top of each other, each pair a stretch of line whose colour was whichever edge painted last. Three quarters of Exoddus' sat at the seven nodes of degree seven and up that the diagram exists to show; Oddysee's split about evenly with the rest, which is why the fix is every box's business and not the hubs'. The ordering is what makes the spread crossing-free rather than merely spread out, and `tests/unit/worldgraph.test.js` sweeps the shipped data for both: no two edges along one stretch of line, and no stub crossing another out of the same side of a box.
  - An Exoddus level's ender half is a contiguous tail of the walk in all five levels that have one, so the break before it is one row offset per column rather than a test per row, and the caption sits in the gap that offset opens. It costs no height: the tallest column in either game has no section.
  - A hover leg is emitted per segment rather than per route, because `#anchorTip` places itself against its anchor's box and a route's whole box can be most of the diagram; the `<g>` around them is what still lights the line entire, through `:has`.
  - Nodes are buttons, so the keyboard reaches every path in the game and a click travels there. The diagram opens scrolled to the path in hand with the focus on it and afterwards only keeps it in view, so `[` / `]` never step the highlight off screen. Focus goes back to whatever opened the mode — and the collapsed drawer being `inert`, an opener behind one hands the keyboard to the menu button instead.
  - It drags to pan like the map, mouse and pen only — touch already pans the scroller with one finger. A plain mouse reaches the bottom of a 3491px-wide diagram with the scrollbar and never the right of it, and the horizontal scroll a trackpad has is no gesture a wheel offers. A drag that ends on a box must not count as a click on it, which is asked of the pointer's own `detail` rather than of a flag the next activation would find: a keyboard Enter reports no presses and so is never the one swallowed.
  - The map's own keys stop at a capture-phase listener of its own rather than at a guard in [js/interaction.js](../public/js/interaction.js): they would flip overlays nobody can see, open a panel over the diagram, or — `s` — silently re-centre the map and rewrite the ruler and every route waypoint. It yields Escape to an open dialog by looking for `.overlay.open`, because `interaction.js` imports this module and so every dialog's trap registers after it — and otherwise stops Escape where it lands, so one press closes one thing, dismissing the anchored tooltip itself since it may be showing an edge's.
  - Clicking a box closes the diagram, which hands the rest of that gesture to the canvas underneath: without a guard the second click of a double-click lands on the map and adds a route waypoint or opens a screen list nobody asked for. [js/interaction.js](../public/js/interaction.js) arms one on the close and clears it on the next press whose `detail` says it begins its own sequence, so nothing is timed. The covered canvas also gives up its accessible name while the mode is up, or a reader would be told about a map that is not on screen — and told again on every selection, since that name is rewritten each time.
  - The mode rides the hash as a bare `graph` token in the tail, which is what makes the diagram shareable and what closes it on the back button. An older deployed viewer drops an unknown tail token and opens the map at the view the link names.
  - `map-data.test.js`'s pinned cross-level follows are the aggregation's oracle: the graph's own crossings expand back to exactly those strings, and a mismatch is the graph's bug.
  - [js/graphsvg.js](../public/js/graphsvg.js) is the diagram's second renderer, and the export is what it exists for: bare-Node importable, it serializes the same `worldGraph` + `graphLayout` into one self-contained SVG — presentation attributes only, the `:root` palette resolved by hand and pinned against the stylesheet by test (`tests/unit/graphsvg.test.js`), since a standalone file cannot ask for `var()`. It owns the edge markup (`marker`/`wirePath`), which graphview imports, so the one-way head rule exists once; a reverse-only route is emitted backwards under a plain `orient="auto"` head, SVG2's `auto-start-reverse` being a feature librsvg gained only in 2.51.3 and older wiki thumbnailers still lack. [js/export.js](../public/js/export.js) owns the bar's two save buttons: the SVG is the string in a file, the PNG the same string rasterized through `sizedCanvas` at 2x falling to 1x with a toast — the scale goes into the SVG's root over a constant viewBox, so an engine that rasterizes at intrinsic size is still crisp. On narrow the save pair hides beside the legend: the title is the bar's one caption, and two wrapped labels were what crushed it — check the bar at 320 and 360 alongside the place chip's own narrow widths. The `-demos` filename marker is read off the built nodes, never the setting, so Oddysee never wears it and a session-revealed demo copy marks the file that really differs — `-edited` follows it the same way, off `pathEdited` over the nodes; the standing-here outline and everything hover-produced stay out — the map export's `transients` rule ([docs/viewer-geometry.md](viewer-geometry.md#the-one-painter-and-the-whole-path-export)) — so two exports of one game are byte-identical.
  - Deliberately not `.chrome`: an embed on a wiki page is exactly where "how does this place connect to the rest" gets asked.
