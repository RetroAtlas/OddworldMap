# 29. Decomp label-correctness sweep

**Status:** ongoing · **Effort:** alive_reversing PRs plus a sidecar regen · **Where:** anywhere — the scans read committed caches, the regen needs no disc

## What and why

A field label is only as good as the decomp's declaration behind it, so a field declared as the wrong type — or as a bare int where an enum belongs — renders raw or, worse, renders as the wrong word. The `chase_abe_when_spotted` fix (merged, [PR #1697](https://github.com/AliveTeam/alive_reversing/pull/1697)) was one misdeclaration; a full `objects_{ao,ae}.json` type scan showed it was the *only* one of its kind — every other cross-carrier type difference (`start_state`, `grab_direction`, `off_sound`, `type`) is a legitimate per-object enum. Two more were raised upstream that a *type* scan cannot catch:

- **ContinuePoint `scale` values possibly swapped** — the decomp has two scale enums for different objects and the checkpoint's may be reversed (full↔half). A *value*-correctness bug, invisible to a type scan.
- **AO `PathTransition` `level` not using `LevelIds`** — a bare int where the enum belongs, so it renders raw. The "missing enum" class, the same family as the numeric fields in [28](item-028-readable-units.md).

## Sketch

The type-inconsistency scan is done (only `chase_abe`). Value-swaps and missing-enums need eyeballing — the map itself is now the tool (search a suspect field, or pan-zoom-click), or diff enumerator order against the raw values in `map_data`. Each confirmed fix is an `alive_reversing` PR to **master's** version converter (bump `kApiVersion`, add an `UpgraderAE`/`AO` step remapping old maps), then regenerate the sidecars here — better labels in the viewer, a faithful decomp upstream.

**Batch the upstream fix — do not ship a single-field PR.** One PR should fix the whole *confirmed* set at once: change the bare `s16` decls to their enum type in `Tlvs{AO,AE}.hpp` / the `AliveLib*` headers, bump `kApiVersion`, and add an AE **and** an AO upgrade step registered with `ADD_UPGRADE_STEP_FROM` — `LevelIds` numbers → labels for `level`, and whatever the value-check confirms beside it. One version bump per class is the upstream preference, since the relive submodule is not re-pinned on every change. Then regenerate the two sidecars, and `PathTransition`'s `level` starts reading as words with zero viewer change.

`_FIELD_TYPE_OVERRIDES` can't do this locally — it only *corrects* an existing type, it can't *add* one to a bare-int field; and per [docs/decomp.md](../docs/decomp.md)'s policy decomp quirks are fixed upstream and re-pinned, never by patching the local checkout.

**Why the parsers target `master`.** AliveTeam's released level editor pins `alive_reversing` **master** (`e2badb8df`) as its submodule, so the declarations these parsers read are the declarations the tooling built on the decomp uses. That is the whole argument. The `beta` branch is a ~1783-commit refactor (measured 2026-07-31: 1783 ahead of master, 42 behind) with a different JSON schema and a rewritten relive_api, so `parse_member_types` / `parse_object_schema` / `parse_enum_labels` would each need a rewrite to read it; if it ever becomes the base, that rewrite is the cost. See [42](item-042-level-editor.md), which established the pin.

## Findings

**Missing-enum scan (2026-07-23):** a "sometimes-typed, sometimes-bare" scan over `objects_{ao,ae}.json` — a field name that is enum-typed on some carriers but a bare `s16` on others, the pattern a missing enum leaves — surfaces the candidates in one shot.

- **`scale` — not an upstream fix at all.** Every carrier the scan surfaced declares `Scale_short` where this repo's parser cannot see: nine inside a `_data` sub-struct the CTOR reads through a dotted arm, `MovingBomb` on the one `class`-declared `Path_*`, `SligGetPants` on an uppercase member, and the wells on a base struct ([41](item-041-inherited-field-types.md) types those now). A scan over the schema cache is blind to whatever the parser misses, so there is nothing here to send upstream; the parser gaps were [92](item-092-member-type-parser-blind-spots.md)'s, and closing them on 2026-09-19 is what made every one of them read full/half.
- **`level` — confirmed missing-enum.** Bare on AE `PathTransition` (should be `LevelIds`) — the same report as the AO `PathTransition` one above, on the AE side. Teleporter's is declared `LevelIds` inside `Path_Teleporter_Data`, the sub-struct arm again, not upstream's.
- **Candidates needing a value-check (name-collision, not yet confirmed):** AO `action` (DeathDrop), `speed` (Bat/Bees/MeatSaw/MotionDetector/MovingBomb/RollingBall/BeeSwarmHole), `type` (BellSongStone), `persist_offscreen` (Mudokon); AE `start_direction` (Drill/FlyingSlig/FlyingSligSpawner/Slurg/SlurgSpawner), `persistant` (FlyingSlig/Spawner), `spawn_delay_state` (FlyingSlig/Spawner), `sound_direction` (CrawlingSligButton), `stay_awake` (SligSpawner), `state` (TimedMine), `behavior` (Drill), `colour` (DoorFlame). Some are real missing-enums, some legitimately different fields, and several sat typed behind the same parser gaps — eyeball each against the decomp, never the cache, before touching upstream.

  Five of the twelve were the parser's and are answered (2026-09-19): [92](item-092-member-type-parser-blind-spots.md)'s arm walk types `type` (BellSongStone), `start_direction` (all five carriers), `persistant`, `spawn_delay_state` and `behavior` off declarations the decomp already carried, so none of them is an upstream question. The seven still to eyeball are AO `action`, `speed` and `persist_offscreen`, and AE `sound_direction`, `stay_awake`, `state` and `colour`.

**ContinuePoint `scale` — confirmed reversed (2026-08-23).** `Path_ContinuePoint::Scale` is declared `{eNone_0, eHalf_1, eFull_2}`, and `Abe::vOn_TLV_Collision_44B5D0` admits `eHalf_1` only where Abe's sprite scale is `FP_FromInteger(1)` and `eFull_2` only where it is `FP_FromDouble(0.5)` — each of the two values gates the plane its own name denies, while `eNone_0` satisfies both clauses and filters nobody. The shipped placements side with the code: 7 of the 8 points at value 1 sit over foreground collision, 10 of the 16 at value 2 over background collision, and the 83 at value 0 are the unfiltered majority. Reproduce by reading the two clauses beside a scan of `map_data_ae.json` for each point's neighbouring line types (background is the half-scale raycast mask, types 4-7).

This is the one member of the set with no wrong *declaration* to fix, and whether the enumerators are misnamed or the game reads them inverted cannot be told from the binary. It is also the cheapest: renaming the two enumerators needs no upgrade step, the stored value being unchanged and only its label moving. Nothing ships wrong today — `glossary_fields.json`'s def for the type states the inversion outright, and that clause is what a rename would retire. There is no local fallback in either direction: `parse_enum_labels` takes the decomp's `AddEnum` names as given, so correcting a label here would mean a corrections table of its own beside `_FIELD_TYPE_OVERRIDES`.

**Which tree the version numbers describe (checked 2026-07-31).** The sibling `alive_reversing` checkout sits on `master` at `e2badb8df` (2026-02-26), and there `kApiVersion = 4`, the newest registered upgrade steps are `UpgraderAO3`/`UpgraderAE3`, and SligSpawner's `chase_abe_when_spotted` is still declared `XDirection_short` — so PR #1697 and any version bump past 4 are upstream of the pin, not in it. Fetch master and re-read the version and the newest upgrade step before opening the PR, rather than carrying a number from here; and note that the override correcting `chase_abe_when_spotted` is still load-bearing against the pinned tree.

**Recorded so it isn't re-proposed as the reason:** what makes master the right base is the editor's pin, not the state of the `beta` branch.
